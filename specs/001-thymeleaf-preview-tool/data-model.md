# Data Model: Thymeleaf Preview Tool

**Date**: 2025-12-24
**Plan**: [plan.md](./plan.md)

## Overview

This document defines the data structures used in the Thymeleaf Preview Tool.
The tool operates on file-system resources and JSON definitions; there is no
database persistence.

---

## Entities

### 1. PreviewProperties

Configuration properties loaded at startup from CLI args or environment
variables.

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| templatesRoot | Path | Yes | Absolute path to Thymeleaf template directory |
| defsRoot | Path | Yes | Absolute path to JSON definitions directory |
| serverPort | int | No | HTTP server port (default: 8080) |

**Validation Rules**:
- templatesRoot MUST exist and be readable
- defsRoot MUST exist and be readable
- serverPort MUST be in range 1-65535

---

### 2. PreviewRequest

Parameters for rendering a template preview.

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| tpl | String | Yes | Relative path to template (e.g., "pages/index.html") |
| fragment | String | No | Fragment name to render (e.g., "header") |

**Validation Rules**:
- tpl MUST NOT contain path traversal sequences (../)
- tpl MUST end with .html
- fragment, if provided, MUST match a valid th:fragment in the template

---

### 3. TemplateInfo

Metadata about a template file, used in catalog listings.

| Field | Type | Description |
|-------|------|-------------|
| path | String | Relative path from templatesRoot |
| name | String | File name without path (e.g., "index.html") |
| directory | String | Parent directory path |
| lastModified | Instant | Last modification timestamp |
| previewUrl | String | URL to preview this template |

**Derived Fields**:
- previewUrl = `/preview?tpl=` + path

---

### 4. DefinitionData

Merged JSON data passed to templates during rendering.

| Field | Type | Description |
|-------|------|-------------|
| css | List<String> | CSS file paths to inject |
| js | List<String> | JavaScript file paths to inject |
| fixtures | Map<String, Object> | Arbitrary mock data for template variables |

**JSON Structure (global.json)**:
```json
{
  "css": ["/assets/css/main.css", "/assets/css/preview.css"],
  "js": ["/assets/js/app.js"],
  "fixtures": {
    "siteName": "Preview",
    "currentYear": 2025
  }
}
```

**Merge Behavior**:
- Arrays (css, js): template-specific values REPLACE global (no append)
- Objects (fixtures): deep merge, template-specific keys override global

---

### 5. CatalogPage

Paginated list of templates for catalog display.

| Field | Type | Description |
|-------|------|-------------|
| templates | List<TemplateInfo> | Templates on current page |
| totalCount | int | Total number of matching templates |
| page | int | Current page number (0-indexed) |
| pageSize | int | Number of items per page |
| hasMore | boolean | Whether more pages exist |
| searchTerm | String | Active search filter (null if none) |

---

### 6. ErrorInfo

Error information for display in error pages.

| Field | Type | Description |
|-------|------|-------------|
| type | String | Error category (NOT_FOUND, INVALID_JSON, etc.) |
| message | String | Human-readable error message |
| path | String | File path related to error (if applicable) |
| line | Integer | Line number in file (for parse errors) |
| suggestion | String | Remediation guidance |

---

## Relationships

```text
PreviewProperties
    └── configures → TemplateService, DefinitionService, CatalogService

PreviewRequest
    └── processed by → PreviewController
    └── resolves to → Template file in templatesRoot
    └── loads → DefinitionData from defsRoot

TemplateInfo
    └── enumerated by → CatalogService
    └── grouped into → CatalogPage

DefinitionData
    └── merged from → global.json + template-specific.json
    └── injected into → Thymeleaf Model

ErrorInfo
    └── generated by → GlobalExceptionHandler
    └── displayed in → error.html template
```

---

## State Transitions

No state machines exist in this application. All entities are read-only
representations of file-system state at request time.

---

## File System Layout

### templatesRoot (read-only)
```text
/path/to/templates/
├── pages/
│   ├── index.html
│   └── about.html
├── components/
│   ├── header.html
│   └── footer.html
├── css/
│   └── style.css
└── js/
    └── app.js
```

### defsRoot (managed)
```text
/path/to/defs/
├── global.json                 # Applies to all templates
├── pages/
│   ├── index.json              # Overrides for pages/index.html
│   └── about.json              # Overrides for pages/about.html
└── components/
    └── header.json             # Overrides for components/header.html
```

## JSON Schema

### global.json / template-specific.json
```json
{
  "$schema": "http://json-schema.org/draft-07/schema#",
  "type": "object",
  "properties": {
    "css": {
      "type": "array",
      "items": { "type": "string" },
      "description": "CSS file paths to inject"
    },
    "js": {
      "type": "array",
      "items": { "type": "string" },
      "description": "JavaScript file paths to inject"
    },
    "fixtures": {
      "type": "object",
      "additionalProperties": true,
      "description": "Mock data for template variables"
    }
  }
}
```
